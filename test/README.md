# test

Scenario tests for the features in `src/`, run with the Dev Container
CLI's `devcontainer features test`.

- **Layout.** `test/<id>/` holds the tests of feature `<id>`:
  `scenarios.json`, one `<scenario>.sh` per scenario, and, for a scenario
  that builds its own image, a `<scenario>/` folder with its `Dockerfile`
  (and any file it copies, such as a `pins.env`). Checks several scenarios
  share go in a `<name>-checks.sh` that each scenario script sources after
  `dev-container-features-test-lib`.
- **Scenarios only.** There is no `test.sh`-driven autogenerated test in
  CI: it installs a feature with its default options, and the features
  have no default pins, so it always fails. Run the scenarios with
  `--skip-autogenerated`.
- **Base images.** An `image` scenario names its image; a `build` scenario's
  `Dockerfile` starts with `ARG BASE_IMAGE` / `FROM ${BASE_IMAGE}` and
  `scenarios.json` passes `BASE_IMAGE` as a build arg. Never use the legacy
  top-level `dockerFile` key.
- **The `features.yml` rewrite.** CI rewrites each `scenarios.json` with
  `jq` before running it, setting every scenario's `image` (or its
  `build.args.BASE_IMAGE`) to the matrix image, so the same scenarios run
  on `devcontainers/base:trixie`, `devcontainers/base:noble`, `debian:13`
  and `ubuntu:24.04`. The image a scenario names is only the local default.
- **`"//renovate"` annotations.** A scenario that sets a `version` option
  has a `"//renovate"` key before it in the same scenario
  (`"datasource=... depName=... [extractVersion=...]"`), so Renovate bumps
  the pinned test version (`.github/renovate.json`); the `ENV` and
  `pins.env` pins use a `# renovate:` comment on the line above instead.
  Renovate bumps only the version, so the shas next to it must be updated
  in the same PR.
- **Negative cases in scripts.** An expected install failure can't be a
  scenario of its own, because a failed install fails the whole run. So a
  `rejects_bad_*` scenario installs a good pin, and its script runs the
  feature's `install.sh` again with bad inputs and checks each failure.
- **`_global`.** `test/_global/` holds cross-feature scenarios (several
  features in one container, such as `ssl-ca` then `cli-s5cmd`), run with
  `--global-scenarios-only`.
